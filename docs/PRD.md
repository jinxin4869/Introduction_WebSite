# PRD：陳 錦鑫 自己紹介サイト

> プロダクトの前提（誰に・何のために）は、ローカルの `PRODUCT.md`（非公開・git 管理外）にまとめてある。この文書は「何を満たせば完成か」を定める。

## 1. 目的

採用担当・案件の依頼者が、リンクを開いてから **2〜3分のスクロールで人柄と経歴を把握できる** 状態にする。
問い合わせ数は KPI にしない。成功は「読んで伝わること」。

## 2. 対象ユーザーと利用シーン

| ユーザー | きっかけ | 知りたいこと | 滞在 |
|---|---|---|---|
| 採用担当・面接官 | 応募書類・スカウト文面のリンク | 現職・経歴の流れ、技術スタック、学び続けているか | 短い（1〜3分）、PC中心 |
| 副業・案件の依頼者 | SNS・知人経由のリンク | 何ができるか、連絡手段 | 短い、スマホ比率高め |
| 本人 | ― | 新しい技術（three.js 等）の試験運用 | ― |

## 3. 機能要件

### 必須（Must）

| ID | 要件 | 現状 |
|---|---|---|
| F-1 | ファーストビューで名前・肩書き・現職が分かる | 済 |
| F-2 | 自己紹介（プロフィール文、所在地、趣味、資格） | 済 |
| F-3 | スキル（言語・フレームワーク・ツール）とプログラミング歴 | 済 |
| F-4 | 職歴・学歴を時系列で表示 | 済 |
| F-5 | 連絡手段（メールアドレス）と GitHub へのリンク | 済（`mailto:` リンク） |
| F-6 | セクション間を移動するナビゲーション（PC／モバイル） | `feature/responsive` で対応 |
| F-7 | スマートフォン幅（375px）で横スクロールせず全内容が読める | `feature/responsive` で対応 |
| F-8 | リンク共有時に OGP（タイトル・説明・画像）が出る | 済（画像はパンダのイラスト。専用の 1200×630 画像は未作成） |

### 推奨（Should）

| ID | 要件 | 現状 |
|---|---|---|
| S-1 | 個人開発（Otter Bank）の概要・使用技術・担当範囲を示す | リンクのみ |
| S-2 | ヒーローの水墨インク背景（WebGL）と、非対応環境での静止画フォールバック | 済 |
| S-3 | `prefers-reduced-motion` で全アニメーションを止める | 済 |
| S-4 | favicon | 済（落款の「陳」の SVG） |

### 決定済み

| ID | 論点 | 決定 |
|---|---|---|
| U-1 | お問い合わせフォーム | 送信ボタンを押すと、入力内容を差し込んだメール作成画面（`mailto:`）を開く。サーバーも外部サービスも使わない。自動で送信する必要が出たら、Formspree 等を再検討する |

### やらないこと（Won't）

- ブログ・CMS 連携、多言語化、PWA（現時点では、利用シーンに対して過剰）。
- スキルの%表示（根拠のない数値になるため。タグ表示に移行済み）。

## 4. 非機能要件

| 項目 | 基準 |
|---|---|
| 表示速度 | モバイルの LCP 2.5 秒以内。WebGL は低スペック端末で起動しない |
| アクセシビリティ | 本文コントラスト WCAG AA（4.5:1）、キーボード操作、reduced-motion の尊重 |
| 互換性 | 最新2バージョンの Chrome / Safari / Firefox / Edge、iOS Safari |
| ホスティング | GitHub Pages。ビルドなしで配信できる構成を維持する |
| 内容の正確さ | 経歴・数値は事実に限る（推薦文・未公開の制作物・数値化されていない成果などを捏造しない） |
