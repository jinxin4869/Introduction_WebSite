# PRD：陳 錦鑫 自己紹介サイト

> プロダクトの前提（誰に・何のために）は [`/PRODUCT.md`](../PRODUCT.md) にまとめてある。この文書は「何を満たせば完成か」を定める。

## 1. 目的

採用担当・案件の依頼者が、リンクを開いてから **2〜3分のスクロールで人柄と経歴を把握できる** 状態にする。
問い合わせ数は KPI にしない。成功は「読んで伝わること」。

## 2. 対象ユーザーと利用シーン

| ユーザー | きっかけ | 知りたいこと | 滞在 |
|---|---|---|---|
| 採用担当・面接官 | 応募書類・スカウト文面のリンク | 現職・経歴の流れ、技術スタック、学び続けているか | 短い（1〜3分）、PC中心 |
| 副業・案件の依頼者 | SNS・知人経由のリンク | 何ができるか、連絡手段 | 短い、スマホ比率高め |
| 本人 | ― | 新しい技術（three.js 等）の試験運用 | ― |

## 3. 機能要件

### 必須（Must）

| ID | 要件 | 現状 |
|---|---|---|
| F-1 | ファーストビューで名前・肩書き・現職が分かる | 済 |
| F-2 | 自己紹介（プロフィール文、所在地、趣味、資格） | 済 |
| F-3 | スキル（言語・フレームワーク・ツール）とプログラミング歴 | 済 |
| F-4 | 職歴・学歴を時系列で表示 | 済 |
| F-5 | 連絡手段（メールアドレス）と GitHub へのリンク | 済（メールはテキストのみ） |
| F-6 | セクション間を移動するナビゲーション（PC／モバイル） | **PCのみ。モバイルでハンバーガーが表示されない** |
| F-7 | スマートフォン幅（375px）で横スクロールせず全内容が読める | **未達：2カラムのまま縮まない** |
| F-8 | リンク共有時に OGP（タイトル・説明・画像）が出る | **未実装** |

### 推奨（Should）

| ID | 要件 | 現状 |
|---|---|---|
| S-1 | 個人開発（Otter Bank）の概要・使用技術・担当範囲を示す | リンクのみ |
| S-2 | ヒーローの水墨インク背景（WebGL）と、非対応環境での静止画フォールバック | 済 |
| S-3 | `prefers-reduced-motion` で全アニメーションを止める | WebGL のみ対応。CSS アニメ・タイピングは未対応 |
| S-4 | favicon | 未実装 |

### 未決定

| ID | 論点 | 選択肢 |
|---|---|---|
| U-1 | お問い合わせフォーム | (a) Formspree 等で実際に送信する / (b) フォームを外し `mailto:` とアドレスのコピーにする |

**U-1 の注意**：今のフォームは送信したように見えるが、実際には誰にも届かない。決定するまでは、フォームを非表示にするか「準備中」と明示することを推奨する。依頼者が「送った」と思い込んで返事を待つのが最悪のケースになる。

### やらないこと（Won't）

- ブログ・CMS 連携、多言語化、PWA（現時点では、利用シーンに対して過剰）。
- スキルの%表示（根拠のない数値になるため。タグ表示に移行済み）。

## 4. 非機能要件

| 項目 | 基準 |
|---|---|
| 表示速度 | モバイルの LCP 2.5 秒以内。WebGL は低スペック端末で起動しない |
| アクセシビリティ | 本文コントラスト WCAG AA（4.5:1）、キーボード操作、reduced-motion の尊重 |
| 互換性 | 最新2バージョンの Chrome / Safari / Firefox / Edge、iOS Safari |
| ホスティング | GitHub Pages。ビルドなしで配信できる構成を維持する |
| 内容の正確さ | 経歴・数値は事実に限る（PRODUCT.md「ないもの」を参照） |
